# Do_Bi · AI 小说写作工具 · 项目规划与技术方案

> 版本：**v2.0**（功能取舍清单版）
> 形态：Web 自托管　|　AI：**全部通过 API 接入**（不含本地模型）
> 合规事项：由项目负责人另行处理，本文档不作约束

---

## 1. 项目概览

### 1.1 一句话定位

**一个「写得出、不崩、可干预」的长篇小说创作工具**——人和 AI 共用同一条创作流水线，既能陪写，也能全自动跑完整本。

### 1.2 目标用户

| 用户 | 核心诉求 | 对应能力 |
|---|---|---|
| 网文作者 | 快速产出初稿、稳定更新、不崩设定 | 一致性引擎 + 全自动模式 |
| 个人创作者 / 爱好者 | 有想法但写不动，需要陪练 | 对话式共创 + 逐章确认 |
| 工作室 / 小团队 | 批量生产、提示词可复用 | 提示词工坊 + 多项目并行 |

### 1.3 核心价值主张

现有工具两极分化：**重表单型**（填十几个字段才有产出）和**一键傻瓜型**（前 5 章惊艳，第 10 章开始人设崩塌、伏笔遗忘、无限水文）。Do_Bi 站在中间：

- **Chat-first**：从一句话灵感开始，不填表
- **强一致**：结构化的「真相文件」承载长期记忆，跨几十万字不漂移
- **双模式**：同一套引擎支持「人机协同」与「全自动」，随时切换
- **可控可查**：每个环节可确认、可回滚，审计结论必须可举证

### 1.4 非目标（明确不做）

- ❌ 本地模型推理 / Ollama 集成（走 OpenAI 兼容 API 统一接入）
- ❌ 多人实时协作编辑
- ❌ 平台发布、排版出版、封面生成
- ❌ 自训练 / 微调模型

## 2. 功能取舍清单（核心）

> 本清单是 v2.0 的主线。**采纳范围**决定做多少，**落点模块**决定放哪儿，**阶段**决定什么时候做。
> 采纳度取值：`全面采纳` / `部分采纳`（注明裁剪） / `暂缓` / `不采纳`。

### 2.1 采纳清单（13 项）

| # | 功能 | 来源 | 采纳度 | Do_Bi 落点 | 阶段 | 说明与边界 |
|---|---|---|---|---|---|---|
| 1 | **真相文件 / 长期记忆** | InkOS | 全面采纳 | `core/store`（项目状态层） | **P0** | 结构化状态 + schema 校验 + Markdown 投影 + 状态增量可回滚。模型只提案，应用裁决 |
| 2 | **审计深度** | InkOS | **部分采纳** | `engine/consistency` | **P0（L1）/ P1（L2 扩容）** | 分两级、分批上。L1 确定性规则 **11 条**先行；L2 起步 5 维、P2 扩到 12 维、P3 按题材定制。**不做成一次上 33 维** |
| 3 | **反 AIGC / 去 AI 味** | InkOS | 全面采纳 | `engine/consistency` + `agents/reviser` | **P1** | 确定性规则（禁止句式、套话密度、连续「了」字、词汇疲劳）为主体；外部检测 API 为可选插件 |
| 4 | **文风仿写** | InkOS | 全面采纳 | `engine/style`（新增） | **P2** | 分析参考文本产出 `style_profile.json`，注入 Writer / Reviser 的系统提示词 |
| 5 | **MCP 扩展** | InkOS | **部分采纳** | `integrations/mcp`（新增） | **P3** | 服务端作为 MCP Client 接入外部工具服务器（资料检索、百科、时间线校验）。**不暴露写权限**，工具结果只进上下文 |
| 6 | **滚动规划（卷弧双层）** | ainovel-cli | 全面采纳 | `agents/architect` + `core/planning` | **P0（基础）/ P1（完整）** | 罗盘 + 骨架弧 + 按需展开 + 渐进细化；节奏模板 P1 再上 |
| 7 | **断点恢复（step 级）** | ainovel-cli | 全面采纳 | `core/checkpoint` | **P0** | 恢复粒度 `plan / draft / audit / revise / commit`；幂等键防重复写入 |
| 8 | **质量评审可举证** | ainovel-cli | 全面采纳 | `engine/consistency`（审计输出格式） | **P1** | 每条审计结论必须带 `dimension / severity / evidence(原文摘录) / suggestion`，无证据不得成条 |
| 9 | **实时干预（Steer）** | ainovel-cli | 全面采纳 | `干预策略层` + SSE 通道 | **P2** | Web 版形态：生成过程中注入指令 → 系统评估影响范围 → 只重写受影响段落，不做全章废弃 |
| 10 | **伏笔可视化** | MuMuAINovel | 全面采纳 | 前端「伏笔」页 + `hooks` 数据 | **P2** | 状态泳道 + 时间线 + 未回收/超期告警；后端在 P0 就产出伏笔数据 |
| 11 | **章纲依赖图 / 思维链** | MuMuAINovel | 全面采纳 | 前端「大纲」页 + `outline.json` | **P2** | 章节依赖图（谁依赖谁的设定/伏笔）+ 规划思维链可视化；数据在 P0/P1 生成 |
| 12 | **拆书** | MuMuAINovel | 全面采纳 | `ingest/disassemble`（新增）+ 导入入口 | **P3** | 导入已有作品 → 反写世界观/角色/大纲/伏笔结构。**仅做结构提取，不做原文存储** |
| 13 | **整本生产流程** | AI-Novel-Writing-Assistant | **部分采纳** | `agents/coordinator`（全自动模式的定义） | **P1** | 采纳其「从一句灵感到成书」的单向生产链路定义，作为全自动模式的流程骨架；其 UI 形态不采纳 |

## 3. 设计原则

1. **模型只负责叙述，应用负责记住真相**
   LLM 输出是「提议」，由应用裁决是否写入正史。
2. **一套流水线，两种干预策略**
   全自动与人机协同是同一条流水线上「干预策略」的不同取值。
3. **先确定性，后智能**
   能用规则零成本判定的问题不用 LLM；LLM 只做规则做不到的事。
4. **审计结论必须可举证**
   没有原文证据的审计条目不予采纳（来自 ainovel-cli 的强约束）。
5. **真相落盘为纯文本**
   Markdown / YAML / JSONL，可 Git 版本化、可人工直接编辑。
6. **分批上线，拒绝一次性做满**
   审计维度、题材规则、可视化面板均分批推进。

## 4. 系统架构

```
┌────────────────────────────────────────────────────────────────┐
│ ① 交互层  工作台 / 共创 / 大纲(依赖图·思维链) / 角色 / 伏笔 / 设置 │
├────────────────────────────────────────────────────────────────┤
│ ② 干预策略层 ★ 手动逐步 / 半自动确认 / 全自动 ＋ 实时干预(Steer)  │
├────────────────────────────────────────────────────────────────┤
│ ③ 编排层  Coordinator → Architect · Writer · Auditor · Reviser   │
│                        · Archivist · Ingestor                    │
├────────────────────────────────────────────────────────────────┤
│ ④ 上下文组装  Token 预算 · 检索 · 关联章节推荐 · 规划罗盘         │
├────────────────────────────────────────────────────────────────┤
│ ⑤ 引擎层                                                         │
│    ├ 一致性引擎  确定性规则 + LLM 维度审计（可举证）+ 修订闭环     │
│    ├ 文风引擎    文风指纹提取 / 注入                              │
│    └ 拆书引擎    结构反写（P3）                                   │
├────────────────────────────────────────────────────────────────┤
│ ⑥ 项目状态层  真相文件（唯一真相源）· 检查点 · 依赖图             │
├────────────────────────────────────────────────────────────────┤
│ ⑦ 集成与模型层  OpenAI 兼容适配层 · MCP Client                    │
└────────────────────────────────────────────────────────────────┘
```

| 层 | 职责 | 关键约束 |
|---|---|---|
| ① 交互层 | 编辑、确认、可视化 | 只调后端 API，不直连模型 |
| ② 干预策略层 | 决定各环节「自动 / 确认 / 手动」＋运行中注入指令 | 策略可全局配、可单环节覆盖 |
| ③ 编排层 | 调度 Agent、维护状态机、断点恢复 | 同一本书串行；薄外壳不做调度决策 |
| ④ 上下文组装 | 在预算内挑最相关信息 | 超限先降级而非报错 |
| ⑤ 引擎层 | 发现问题、修复、风格控制 | L1 确定性优先；审计须举证 |
| ⑥ 项目状态层 | 存储真相与历史 | 纯文本 + 可 Git；写入需经校验 |
| ⑦ 集成与模型层 | 统一模型调用 + 外部工具 | 只依赖 OpenAI 兼容协议；MCP 只读 |

## 5. 数据层设计

### 5.1 项目目录结构

```
projects/<project-id>/
├─ meta.json                  # 元信息：题材、篇幅、模式、预算
├─ world.md                   # 世界观规则（不可违反的硬设定）
├─ characters.jsonl           # 角色矩阵（含不可变特征）
├─ current_state.md           # 世界当前状态快照
├─ pending_hooks.jsonl        # 伏笔池
├─ chapter_summaries.jsonl    # 章节摘要（累积）
├─ subplot_board.md           # 支线进度板
├─ emotional_arcs.md          # 情感弧线                      ← 采纳自 InkOS
├─ particle_ledger.jsonl      # 资源/数值账本（修为·物品·消耗）  ← 采纳自 InkOS
├─ compass.json               # 规划罗盘（终局方向+活跃长线）    ← 采纳自 ainovel-cli
├─ outline.json               # 分卷/分章大纲（含骨架弧）
├─ outline_graph.json         # 章纲依赖图 + 思维链             ← 采纳自 MuMuAINovel
├─ style_profile.json         # 文风档案                       ← 采纳自 InkOS
├─ chapters/ch_0001.md        # 正文
├─ audits/ch_0001.json        # 审计报告（含原文举证）
├─ aigc/ch_0001.json          # 去 AI 味检测报告               ← 采纳自 InkOS
└─ checkpoints/               # step 级执行快照                 ← 采纳自 ainovel-cli
```

### 5.2 关键数据结构

**characters.jsonl** —— 区分「不可变特征」与「可变状态」，防崩核心

```json
{
  "id": "char_001",
  "name": "沈砚",
  "role": "protagonist",
  "immutable_traits": ["左眉骨有旧疤", "不饮酒", "惯用左手"],
  "personality": "沉默寡言，重承诺",
  "speech_style": "短句，很少用感叹词",
  "relationships": [{"target": "char_002", "type": "师徒", "note": "心存愧疚"}],
  "state": {"location": "北境·雁回关", "status": "受伤", "known_secrets": ["文脉真相"]},
  "first_appearance": 1,
  "updated_at_chapter": 17
}
```

**pending_hooks.jsonl** —— 伏笔须可统计回收率（支撑「伏笔可视化」）

```json
{
  "id": "hook_007",
  "content": "沈砚幼年见到的青铜灯并未熄灭",
  "planted_chapter": 4,
  "status": "planted",
  "resolved_chapter": null,
  "importance": "major",
  "linked_characters": ["char_001"],
  "suggested_resolve_by": 40
}
```
`status` ∈ `planted` / `resolved` / `abandoned`。`planted` 且超过 `suggested_resolve_by` → 超期告警。

**particle_ledger.jsonl** —— 资源/数值账本（采纳自 InkOS，防「战力漂移 / 道具凭空出现」）

```json
{
  "item": "青铜灯",
  "holder": "char_001",
  "acquired_chapter": 17,
  "consumable": false,
  "notes": "与 hook_007 同源",
  "last_verified_chapter": 17
}
```

**outline_graph.json** —— 章纲依赖图 + 思维链（采纳自 MuMuAINovel）

```json
{
  "nodes": [
    {"id": "ch_017", "title": "雪落雁回", "status": "audit", "depends_on": ["ch_016", "hook_004"]},
    {"id": "ch_018", "title": "铜灯不熄", "status": "draft", "depends_on": ["ch_017", "hook_007"]}
  ],
  "edges": [
    {"from": "hook_007", "to": "ch_018", "kind": "payoff"},
    {"from": "ch_016", "to": "ch_017", "kind": "causality"}
  ],
  "reasoning": [
    {"step": 1, "note": "先让铜灯亮起（呼应 hook_007），再引出文脉司"},
    {"step": 2, "note": "第 20 章安排第二枚铜牌，与 hook_011 合流"}
  ]
}
```
`edges.kind` ∈ `causality`（因果）/ `payoff`（伏笔回收）/ `setup`（埋伏笔）/ `subplot`（支线交汇）。

**audits/ch_0017.json** —— 审计结论**必须带原文举证**（采纳自 ainovel-cli 的硬约束）

```json
{
  "chapter": 17,
  "rules_violated": 2,
  "dimensions_run": ["设定冲突", "OOC", "视角跳跃", "伏笔遗漏", "文风偏移"],
  "items": [
    {
      "dimension": "设定冲突",
      "severity": "major",
      "evidence": "「灯没有点，可灯芯那一小截，是亮的」",
      "evidence_ref": "17.5",
      "suggestion": "与 world.md「铜灯须以血引方燃」冲突；建议改为割破指尖后灯芯自燃",
      "fixed": false
    }
  ]
}
```
**校验规则**：`evidence` 为空或无法在正文中定位到 → 该条目自动丢弃（不进入报告）。

**aigc/ch_0017.json** —— 去 AI 味检测报告

```json
{
  "chapter": 17,
  "deterministic_rules": [
    {"rule": "套话密度", "hits": 1, "samples": ["极其", "不由得"]},
    {"rule": "连续「了」字句", "hits": 1, "samples": ["他看了看，又走了走"]},
    {"rule": "词汇疲劳", "hits": 2, "samples": ["雪（本章 14 次）", "冷冷地（本章 5 次）"]}
  ],
  "external_detector": {"provider": "可选，未启用", "score": null},
  "spotfix_applied": 1
}
```

**checkpoints/** —— 断点恢复依据（采纳自 ainovel-cli）

`checkpoints/ch_0017_step3_audit.json` 含：`chapter` / `step`(`plan|draft|audit|revise|commit`) / `status` / `attempt` / `idempotency_key` / `output_ref` / `timestamp`。

### 5.3 写入规则（关键）

所有对真相文件的写入必须经过 **Proposal → Validate → Commit** 三步：

1. Agent 产出「提案」（新增事实、修改角色状态、更新账本）
2. 校验器检查：字段合法性、是否违背 `immutable_traits`、是否与 `world.md` 冲突、账本数值是否守恒
3. 通过才落盘；冲突项降级为「待人工确认」，不自动入正史

> MCP 工具返回的内容**只进上下文**，不直接写入真相文件，必须经同一套 Proposal 流程。

## 6. AI 模型接入方案

> 全部通过 API 调用，无本地模型。目标：**换厂商不改业务代码、成本可控、失败可恢复**。

### 6.1 统一适配层

只依赖 **OpenAI 兼容协议**，用官方 `openai` SDK 通过 `base_url` + `api_key` 切换厂商。

| 字段 | 说明 |
|---|---|
| `name` | 展示名，如 `DeepSeek` |
| `base_url` | 兼容端点 |
| `api_key_ref` | 指向环境变量的键名，**不落明文** |
| `models` | 可用模型（含 `context_window`、`supports_json`、`supports_stream`） |
| `priority` | 主/备顺序，构成降级链 |

需处理的厂商差异：`max_tokens` vs `max_completion_tokens`；`response_format` / `json_schema` 支持度不一 → **能力探测 + 自动降级**；并行 tool calls 不支持 → 串行降级。

可接入：OpenAI、Anthropic、Gemini、DeepSeek、通义千问、Kimi、智谱、硅基流动等任意兼容端点。

### 6.2 模型角色分工

| 环节 | 模型档位 | 温度 | 输出格式 |
|---|---|---|---|
| 世界观 / 大纲 / 罗盘（Architect） | 高能力 | 0.7–0.8 | JSON |
| 章纲（含依赖图/思维链） | 高能力 | 0.6 | JSON |
| 正文（Writer） | 高能力 + 长上下文 | 0.85–0.95 | 流式文本 |
| 审计 L2（Auditor） | 中能力（便宜） | 0.1–0.2 | JSON（须含 evidence） |
| 修订（Reviser） | 高能力 | 0.3–0.5 | JSON Patch |
| 去 AI 味改写 | 中能力 | 0.4 | JSON Patch |
| 文风指纹提取（Style） | 中高能力 | 0.2 | JSON |
| 摘要 / 事实抽取 / 账本更新 | 便宜模型 | 0.1 | JSON |
| 拆书结构反写（P3） | 高能力 | 0.3 | JSON |
| 对话式共创 | 中高能力 | 0.6–0.8 | JSON + 文本 |

约束：同一环节的主备模型必须都支持所需能力（如 JSON 模式），否则降级链会中途断掉。

### 6.3 密钥与配置管理

- API Key **只存环境变量 / 服务端密钥库**，前端永不接触
- 前端设置页只展示「已配置 / 未配置」，提交走一次性加密传输
- 日志与错误信息对 Key 脱敏
- 与 Studio/CLI 双轨不同，Do_Bi **单一来源**：服务端配置为准，env 仅作覆盖

### 6.4 调用链与流式（含实时干预）

```
前端 SSE ◄── FastAPI 编排器 ──► 适配层 ──► Provider API
                 │  ▲
                 │  └── 干预通道：POST /steer（生成中注入指令）
                 └─► 逐块转发（可中断 / 可停止）
```

- 正文生成走 **SSE 流式**，支持「停止」立即中止并保存半成品
- **实时干预**：生成中提交指令 → 系统评估影响范围 → 仅重写受影响的段落区间
- 结构化任务（大纲/审计）走非流式
- 下游步骤输入**必须来自落盘数据**，不依赖内存中的对话历史（保证断点可续）

### 6.5 成本与预算控制

1. **每章 Token 预算上限**：超出则裁剪低优先级上下文（而非报错）
2. **上下文分层预算**（默认，可配）

   | 用途 | 占比 |
   |---|---|
   | 系统规则 / 提示词 | 5% |
   | 角色卡 + 世界观 | 15% |
   | 动态事实表 + 账本 | 10% |
   | 历史摘要 | 20% |
   | 当前草稿 | 30% |
   | 输出预留 | 20% |

3. **调用计量**：记录 `model / step / prompt_tokens / completion_tokens / cost / latency`，落库并按项目·章·天聚合
4. **预算熔断**：达阈值提示，超额则暂停并挂起 checkpoint（不静默烧钱）

### 6.6 稳定性设计

| 问题 | 对策 |
|---|---|
| 超时 | 连接超时与读取超时分开配置 |
| 429 / 5xx | 指数退避重试，上限 3 次，加抖动 |
| 4xx 参数错误 | **不重试**，记录并降级或报错 |
| 输出非合法 JSON | 解析容错 → 修复 → 再失败则带错误重试一次 |
| 主力模型不可用 | 降级链：主力 → 备用 → 挂起 checkpoint 并提示 |
| 重试导致重复写入 | 每 step 带 `idempotency_key`，写入前查重 |
| 并发写同一本书 | 项目级锁，串行执行；不同项目可并行 |
| 上下文超窗 | 按预算裁剪；不支持长上下文时自动切摘要模式 |
| 实时干预打断生成 | 记录已产出区间；干预后仅重算受影响区间 |

### 6.7 可观测性

- **调用日志**：请求元信息 + 响应摘要（提示词全文可选开关）
- **审计报告**：每章一份，含维度、严重度、**原文举证**、是否已修复
- **去 AI 味报告**：每章一份，含规则命中与样例
- **质量指标**：伏笔回收率、L1 违规数、审计通过率、AIGC 命中率、每章平均成本
- 前端可见「本章花了多少 Token / 多少钱」

### 6.8 检索方案

**P0 不上向量库**，用 BM25（SQLite FTS5 或 `rank_bm25`）检索设定卡、事实表、历史摘要、账本。数据量小、零额外依赖、离线可用。

接口预留可插拔检索后端，后续可切 embedding + 向量库。

### 6.9 MCP 扩展（P3）

- 服务端作为 **MCP Client**，通过 stdio / SSE 连接外部工具服务器
- 典型用途：资料检索（历史/地理/术语）、百科核对、外部时间线校验
- **安全边界（必须遵守）**：
  - 只授予 **只读工具**，不暴露任何写权限
  - 工具返回内容**只进上下文**，写入真相文件必须走 Proposal → Validate → Commit
  - 每个 MCP 服务器可单独启用/禁用，并在设置页展示其声明的工具清单
  - 调用记录进入调用日志，可审计

## 7. Agent 流水线设计

### 7.1 角色职责

| Agent | 输入 | 输出 | 说明 |
|---|---|---|---|
| **Coordinator** | 用户意图、项目状态 | 调度决策 | 只编排与仲裁，不生成内容（薄外壳） |
| **Architect** | 灵感 / 对话记录 | `world.md`、`characters.jsonl`、`outline.json`、`compass.json` | 建立创作宪法；负责滚动规划 |
| **Writer** | 章纲 + 组装好的上下文 | 正文（流式） | 唯一产出正文的角色 |
| **Auditor** | 正文 + 真相文件 | 审计报告（**须带原文举证**） | L1 规则 + L2 维度 |
| **Reviser** | 正文 + 审计报告 | JSON Patch | 定点修复，最小改动 |
| **Archivist** | 定稿正文 | 摘要、事实抽取、伏笔/账本更新、依赖图更新 | 沉淀为可检索资产 |
| **Ingestor**（P3） | 已有作品文本 | 世界观/角色/大纲/伏笔结构 | 拆书；不存储原文 |

### 7.2 单章执行时序

```
章纲 ──► 上下文组装 ──► 草稿 ──► 审计(L1+L2，须举证) ──► 去AI味 ──► 修订 ──► 定稿 ──► 更新真相
  ▲                        │  ↑                    │                              │
  │                        │  └── 实时干预 Steer ───┘                              │
  └──────── 干预策略层插入「确认点」 ────────────────────────────────────────────────┘
```

每环节结束写 checkpoint。干预策略取值：

- **全自动**：全部 auto（审计问题自动进修订；冲突项标记后继续，不阻塞）
- **半自动**：章纲、审计报告两个节点确认
- **手动逐步**：每环节都停下等确认

### 7.3 整本生产流程（全自动模式的流程骨架）

采纳自 AI-Novel-Writing-Assistant 的单向链路定义：

```
灵感 → 题材/卖点 → 世界观 → 角色 → 罗盘(终局方向) → 第一卷骨架弧
  → 详细章纲 → 逐章(草稿→审计→去AI味→修订→定稿) → 卷边界刷新罗盘 → 下一卷…
  → 完结收束(伏笔总回收校验)
```

约束：
- **单向推进**，不回退重写已成卷（避免级联返工）
- 每卷结束做一次**卷级体检**（伏笔回收率、角色状态一致性、节奏曲线）
- `stop_conditions` 熔断（见 §8）

### 7.4 滚动规划（卷弧双层）

不一次性规划全部章节（大纲到 300 章必然空心化）：

- **罗盘 Compass**：终局方向 + 活跃长线 + 规模估计，每个卷边界刷新
- **按需生成**：初始只规划前 2 卷，当前卷写完才创建下一卷
- **骨架弧**：只记 `目标 + 预计章数`，写到该弧时才展开详细章纲
- **渐进细化**：每次展开参考前文摘要、角色快照、文风规则，越往后越准
- **节奏模板**（P1）：成长突破弧 / 竞技对抗弧 / 探索发现弧 / 恩怨冲突弧 / 日常过渡弧

### 7.5 断点恢复

| 中断时机 | 恢复行为 |
|---|---|
| 规划阶段（正在建世界观/大纲） | 检查已保存设定，自动补全缺失项 |
| 某章正在写作（有草稿未提交） | 从该章续写，读取已有草稿继续 |
| 审计进行中 | 重新触发审计（幂等，不重复计费由缓存保证） |
| 修订队列未清空 | 继续处理待修订条目 |
| 卷/弧展开中断 | 检测骨架弧，自动触发 Architect 展开 |
| 干预处理中 | 恢复到干预前的最后一个 checkpoint |

- 恢复粒度：`plan / draft / audit / revise / commit`
- 幂等：同 `idempotency_key` 的写入只生效一次
- 目标：kill -9 或断网后重启，精确续跑，不重复不丢稿

## 8. 干预策略层

**这是「人机协同」与「全自动」统一的关键。**

```json
{
  "mode": "semi-auto",
  "steps": {
    "plan": "confirm", "draft": "auto", "audit": "confirm",
    "deai": "auto", "revise": "auto", "commit": "confirm"
  },
  "steer": { "enabled": true, "scope": "affected-only" },
  "stop_conditions": ["audit.blocker_exists", "budget.exceeded", "hooks.overdue_rate>0.3"]
}
```

- 每个 step 取值 `auto` / `confirm` / `manual`
- 运行中可随时切换：全自动跑到一半想接管，切 `confirm` 即在下个确认点停下
- **实时干预**：`steer.scope = affected-only` 表示只重算受影响区间，不做整章废弃
- `stop_conditions` 保证全自动模式不会失控烧钱或产出崩溃内容

## 9. 一致性引擎

### 9.1 L1 确定性规则（零 LLM 成本，P0 就做）

| # | 规则 | 支撑的采纳项 |
|---|---|---|
| 1 | 称呼/姓名不一致 | 审计深度 |
| 2 | 角色已标记「死亡/离场」却再次出场 | 审计深度 |
| 3 | `immutable_traits` 被违背 | 审计深度 |
| 4 | 禁用句式 / 套话密度超阈值 | 反 AIGC |
| 5 | 连续「了」「的」字句 | 反 AIGC |
| 6 | 段落长度异常（超长或全篇等长） | 审计深度 |
| 7 | 视角切换未标注 | 审计深度 |
| 8 | 时间线倒错 | 审计深度 |
| 9 | 伏笔超期未回收 | 伏笔可视化 |
| 10 | 数值/资源与账本不符（`particle_ledger` 守恒校验） | 长期记忆 |
| 11 | 词汇疲劳（高频词超阈值） | 反 AIGC |

### 9.2 L2 LLM 维度审计（分批扩容）

**P1 起步 5 维**（每维必须引用原文举证）：

1. OOC（角色出戏，对照 `personality` / `speech_style`）
2. 设定冲突（对照 `world.md`）
3. 伏笔遗漏（该回收未回收）
4. 时间线矛盾
5. 文风偏移（对照 `style_profile.json`）

**P2 扩容至 12 维**：新增 信息泄露（角色知道了不该知道的）、动机薄弱、节奏单调、支线断裂、场景转换生硬、对话同质化、情感弧断裂。

**P3 按题材定制**：每个题材（玄幻/仙侠/都市/悬疑）配一套专属维度与禁忌清单，允许每本书自定义 `book_rules.md`。

### 9.3 审计输出格式（可举证硬约束）

```json
{
  "dimension": "设定冲突",
  "severity": "major",
  "evidence": "「灯没有点，可灯芯那一小截，是亮的」",
  "evidence_ref": "17.5",
  "suggestion": "与 world.md 冲突，建议改为割破指尖后灯芯自燃",
  "fixed": false
}
```

**校验门**：`evidence` 为空、或无法在正文中定位 → 条目自动丢弃。严重度 `blocker / major / minor`。

### 9.4 修订策略

- `blocker` / `major` → **定点修复**：Reviser 输出 JSON Patch（`replace / insert / delete`），前端可预览 diff
- `minor` → 只记录，不自动改
- 自动修订后**必须重跑 L1**（防修订引入新问题），L1 通过才算闭环
- 单章修订循环上限 2 轮，超限挂起交人工

### 9.5 去 AI 味（反 AIGC）

- **主体**：§9.1 中的确定性规则（4/5/11 条为主），零 LLM 成本、100% 稳定
- **定点修复**：命中即触发 spot-fix，只改命中句，不做整章重写
- **外部检测（可选插件）**：GPTZero 等 API，仅在用户显式开启时调用；未启用则报告里标注未启用
- **AIGC 报告**：每章产出 `aigc/ch_XXXX.json`，含规则命中、样例、修复数

## 11. 拆书引擎（P3）

**目标**：导入已有作品 → 反写结构化资产，用于续写或改写。

```
导入文本 → 章节切分 → 逐章抽取(角色/地点/事件/伏笔/数值)
        → 汇总去重 → 生成 world.md / characters.jsonl / outline.json / pending_hooks.jsonl
        → 用户确认 → 写入项目
```

**边界（必须遵守）**：
- **仅做结构提取，不存储原文**（避免版权风险）
- 抽取结果一律进入「待确认」状态，用户确认后才写入真相文件
- 长文本按章流式处理，支持中断续跑（复用 checkpoint 机制）

### 12.2 设计方向（Design Contract 已在原型阶段冻结）

- **Style tier**：`minimal-light` + **literary / editorial（文学编辑风）**
- **气质关键词**：安静、克制、高可读性、编辑级排版
- **字体**：显示字体衬线（`Noto Serif SC`）；正文/UI 用 `Noto Sans SC`；**正文编辑区 18px / 行高 1.95**
- **配色**：暖纸底 + 墨色正文 + 靛蓝主色；朱砂仅用于品牌印与伏笔标记
- **背景**：极淡纸纹（暖色光晕 + 低透明度纤维纹）
- **图标**：统一 Lucide 内联 SVG，禁止 emoji
- **动效**：一次编排好的载入错落浮现 + 克制动效
- **禁止**：白底紫渐变、Inter/Roboto/Arial、emoji 图标、每张卡同一重阴影

> 契约文件：`prototype/do-bi-design-contract.md`（v2.0 需同步新增「大纲 / 文风」两页与导航项）

### 12.3 关键交互

- **流式写作可中断**，随时「停止」并保留半成品
- **实时干预**：生成中在输入框注入指令，仅重写受影响段落
- **diff 预览修订**：可逐条接受/拒绝
- **审计举证可视**：每条结论下方展示原文摘录，可点击跳转到正文位置
- **干预开关常驻**，一键切换
- **成本可见**：每章显示 Token 与费用
- **依赖图交互**：节点可点击跳转到章纲，边可区分因果/伏笔/支线

## 14. 里程碑

> 不含时间估算，只定义交付物与验收标准。

### P0 · 一致性内核（后端 + CLI，不含 UI）

**交付物**
- 项目骨架 + OpenAI 兼容适配层（Provider 配置、重试、降级、计量）
- 真相文件 schema 与读写（Proposal → Validate → Commit），含 **账本 / 情感弧线**
- 上下文组装（Token 预算 + BM25 + 关联章节推荐）
- Architect（含 **罗盘 + 骨架弧**）/ Writer / Auditor(L1，11 条规则)
- step 级 checkpoint 与恢复（含恢复场景表）
- CLI：`novel new / plan / volume next / write <n> / audit / resume`

**验收标准**
1. 一条命令从一句灵感生成 **10 章**正文
2. **伏笔回收率可统计**（埋 N 条、回收 M 条）
3. **角色状态不漂移**：L1 规则零违规
4. **中断可续**：kill 进程后重启，精确续跑，不重复不丢稿
5. **滚动规划生效**：只规划前 2 卷，`volume next` 能按需展开下一卷
6. 每章 Token 与成本可查

### P1 · 双模式流水线

- 干预策略层（auto / confirm / manual）+ `stop_conditions` 熔断
- Coordinator + **整本生产流程**（全自动端到端）
- 审计 **L2 起步 5 维**，输出**强制带原文举证**
- **去 AI 味**（确定性规则 + spot-fix + 可选外部检测）
- 滚动规划完整（节奏模板 + 渐进细化）
- 章纲依赖图 / 思维链**数据生成**

**验收**：全自动模式无人值守写完 20 章；审计条目 100% 带可定位的原文证据；去 AI 味报告可读且命中项已定点修复。

### P2 · Web 工作台

- 按 Design Contract 实现 7 页前端（复用原型）
- **伏笔可视化**（时间线 + 泳道 + 超期告警）
- **大纲页**（依赖图 + 思维链）
- **实时干预 Steer**（生成中注入 + 仅重算受影响区间）
- **审计举证可视化**（原文摘录 + 跳转）
- **文风仿写**（指纹提取 + 注入 + 可手工微调）
- 审计 L2 扩容至 12 维

**验收**：浏览器内完成「立项 → 逐章确认 → 干预 → 定稿」全流程；伏笔告警、依赖图、文风档案均可用。

### P3 · 增强与扩展

- **拆书**（结构反写，不存原文）
- **MCP 扩展**（只读工具 + 工具清单展示）
- 题材规则库（5 个内置题材 + 每书 `book_rules.md`）
- 外部 AIGC 检测 API 接入
- 审计按题材定制维度

**验收**：能导入一部已有作品反写出可用设定；MCP 工具结果可进上下文且不越权写入。

## 16. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **范围爆炸**（最大风险） | 永远发不了版 | P0 严格限定「后端内核 + CLI」；13 项采纳功能按 P0–P3 分流，不提前 |
| 审计维度做太多 | 成本↑、调参失控 | 分批：L1 11 条 → L2 起步 5 维 → P2 扩到 12 维 → P3 按题材 |
| **实时干预实现复杂** | 打断生成导致状态错乱 | 记录已产出区间，仅重算受影响段；干预前先落 checkpoint |
| Token 成本失控 | 用户流失 | 分层预算 + 熔断 + 成本可见 |
| 全自动质量天花板 | 产出不可用 | 审计只做能做的；冲突项标记待人工，不追求 100% 自动 |
| 修订死循环 | 烧钱 | 单章修订上限 2 轮，超限挂起 |
| 模型输出格式不稳 | 流程中断 | JSON 解析容错 + 能力探测降级 + 重试带错误上下文 |
| **审计幻觉**（编造问题） | 用户丧失信任 | **强制原文举证 + 定位校验**，定位不到即丢弃条目 |
| 依赖图与正文不一致 | 可视化误导 | 依赖图只在 Archivist 定稿时更新，不由模型自由编辑 |
| MCP 越权 | 数据被污染 | 只读工具、结果只进上下文、写入须走 Proposal 流程 |
| 文风仿写走样 | 产出风格崩 | 指纹可人工微调；文风偏移作为 L2 独立维度持续校验 |
| 厂商锁定 | 可用性风险 | 只依赖 OpenAI 兼容协议，Provider 可配置可替换 |

## 17. 术语表

| 术语 | 含义 |
|---|---|
| 真相文件 | 承载长期记忆的结构化文件，唯一真相源（采纳自 InkOS） |
| 罗盘 Compass | 记录终局方向与活跃长线的规划锚点（采纳自 ainovel-cli） |
| 骨架弧 | 只记 `目标 + 预估章数`、写到才展开的规划单元（采纳自 ainovel-cli） |
| 干预策略 | 决定流水线各环节自动/确认/手动的配置 |
| 实时干预 Steer | 生成过程中注入指令、仅重算受影响区间（采纳自 ainovel-cli） |
| L1 / L2 审计 | L1 确定性规则（零 LLM 成本）；L2 LLM 维度审计 |
| 原文举证 | 审计条目必须附正文摘录且可定位，否则丢弃（采纳自 ainovel-cli） |
| 依赖图 | 章纲与伏笔/因果/支线的有向图（采纳自 MuMuAINovel） |
| 思维链面板 | 展示规划决策过程的可视化面板（采纳自 MuMuAINovel） |
| 拆书 | 导入已有作品反写结构资产，不存原文（采纳自 MuMuAINovel） |
| 账本 Ledger | 资源/数值守恒记录，防战力漂移（采纳自 InkOS） |
| 文风指纹 | 从参考文本提取的可注入风格档案（采纳自 InkOS） |
| JSON Patch | 修订输出的标准补丁格式（replace / insert / delete） |
| checkpoint | step 级执行快照，用于断点恢复 |
| stop_conditions | 全自动模式的强制中断条件 |
